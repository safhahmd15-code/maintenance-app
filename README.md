# نظام إدارة طلبات الصيانة (Maintenance Request Management System)

تطبيق Flutter لإدارة طلبات الصيانة داخل شركة صغيرة، تم تطويره كتكليف عملي لتحديد مستوى المتدربين لدى Third Eye Software - مسار Flutter.

## المشكلة التي يحلها

الموظفون في الشركة يواجهون مشاكل متكررة بأجهزة الكمبيوتر والطابعات والإنترنت والبرامج، ويتم حاليًا إبلاغ مسؤول الصيانة عبر واتساب أو بشكل شفهي، مما يؤدي أحيانًا لضياع الطلبات أو نسيانها، وعدم معرفة الموظف بحالة طلبه.

يوفر هذا التطبيق نظامًا مركزيًا لتسجيل الطلبات ومتابعتها وإدارتها إلكترونيًا.

## المستخدمون

- *Employee (موظف):* ينشئ طلب صيانة، يتابع حالته، ويشاهد سجل طلباته السابقة.
- *Maintenance Officer (مسؤول صيانة):* يشاهد جميع الطلبات الواردة، يغيّر حالتها، ويضيف ملاحظات عليها.

## أهم المميزات

- تسجيل دخول آمن عبر Firebase Authentication
- توجيه تلقائي للواجهة المناسبة حسب دور المستخدم (Role-Based Navigation)
- إنشاء طلبات صيانة جديدة (عنوان، وصف، تصنيف، أولوية)
- متابعة حالة الطلب لحظيًا (New / In Progress / Resolved / Reopened)
- إضافة ملاحظات على الطلبات من قبل مسؤول الصيانة
- سجل الطلبات السابقة والملف الشخصي لكل مستخدم
- قائمة جانبية (Side Menu) تحتوي على الملف الشخصي وسجل الطلبات وتسجيل الخروج

## التقنيات المستخدمة

- *Flutter* (Dart) - بناء واجهة التطبيق
- *Firebase Authentication* - إدارة تسجيل الدخول
- *Cloud Firestore* - قاعدة بيانات لحظية لتخزين الطلبات والملاحظات وبيانات المستخدمين

## إعداد Firebase

يعتمد المشروع على:
- *Firebase Authentication* مع تفعيل خيار Email/Password
- *Cloud Firestore* بالمجموعات (Collections) التالية:
- users - بيانات المستخدمين وأدوارهم
- maintenance_requests - طلبات الصيانة
- maintenance_notes - الملاحظات المرتبطة بكل طلب

*ملاحظة:* الحسابات تُنشأ حاليًا يدويًا عبر Firebase Console (Authentication + إضافة ملف شخصي مطابق بمجموعة users)، إذ لا توجد شاشة تسجيل حساب جديد (Sign Up) ضمن نطاق هذا الإصدار من المشروع.
